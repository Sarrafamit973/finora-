# Finor

Finor is a responsive market dashboard built with Vite, React, and TypeScript. It presents a polished overview of market data, charts, news, and asset analysis in a single browser-based interface.

The project is a static front-end application designed to run in a browser without a backend service. It is suitable for deployment on static hosting providers such as Vercel or Netlify.

## Overview

The app includes:

- Home dashboard with market overview tiles
- Markets section with category-based listings and sorting/search controls
- Charts page with quick asset summaries and detail views
- News page for financial article summaries
- Analysis page with narrative asset commentary
- Watchlist page for tracked instruments
- A not-found route fallback for unmatched pages

## Technology Stack

- React 19
- TypeScript
- Vite 8
- React Router DOM
- CSS modules via standard stylesheet files
- Static hosting model (no server-side runtime in the current implementation)

## Deployment

This project is a static frontend and is best suited for static hosting services.

### Recommended platforms

- Vercel
- Netlify
- GitHub Pages with SPA compatibility handling

### Important routing requirement

Because the app uses `BrowserRouter`, the hosting platform must redirect unknown paths to `index.html`. This is required for direct URL access and full-page refreshes to work properly.

#### Netlify example

Add a redirect rule in the hosting configuration or a `public/_redirects` file:

```text
/*    /index.html   200
```

#### Vercel example

Use a `vercel.json` rewrite:

```json
{
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

#### GitHub Pages note

GitHub Pages does not natively support SPA rewrites in the same way as Netlify or Vercel. If deployed there, use a compatible SPA workaround or switch to a hash-based router.

## Known Limitations

- The app uses static mock market data instead of a live market-data API.
- There is no backend, authentication layer, or database in the current implementation.
- Data and analysis are designed for demonstration and browsing rather than production-grade financial tooling.
- Direct deep-link routing requires hosting config for static SPA deployment.

## Public Deployment Notes

Before publishing:

- Run `npm run build` to validate the production bundle
- Ensure the host rewrites SPA routes to `index.html`
- Confirm the favicon and static assets load from the public domain
- Test major routes after deployment
- Verify the site behaves correctly on desktop and mobile layouts

## Security Notes

- Do not commit secrets, API keys, or credentials to the repository.
- If live market data or authenticated services are added later, keep credentials in secure server-side or host-managed secret storage.
- This project currently does not contain any checked-in secrets.
